# AGENTS.md

Instructions for AI coding agents working in this repository.

## What this is

Tribunal is a methodology and tooling for adversarial, multi-model review of LLM-written code. It has three parts: a Go CLI (`tribunal`) that keeps a signed findings ledger and runs a verification pyramid, a CosmWasm contract that records per-agent reputation on Burnt XION testnet, and a public Astro site under `site/`. The README calls it "in active development". Releases are tracked in `CHANGELOG.md` (latest entries are v0.5.x). The license is AGPLv3 or later.

## Layout

- `cmd/tribunal/` - the CLI (cobra). Subcommands: agents, ledger, init, review, verify, dispatch, chain, fix, revalidate, converge, history.
- `cmd/seed-fizzbuzz-demo/`, `cmd/tribunal-seed/`, `cmd/tribunal-batch-file/` - helper programs.
- `internal/` - core packages: `ledger`, `dispatch`, `verify`, `chain`, `converge`, `review`, `clawpatch`, `agent`.
- `trajectory/` - trajectory property-based testing package.
- `contracts/tribunal-reputation/` - the Rust CosmWasm reputation contract.
- `skills/` and `agents/` - Markdown skills and agent definitions that `tribunal init` copies into a host harness.
- `docs/` - methodology, incentive math, on-chain protocol, installation, ADRs in `docs/adr/`.
- `examples/` - `go-fizzbuzz-verified` (demo project with a committed demo ledger) and `trajectory-portrait`.
- `.tribunal/reports/` - committed review reports. The rest of `.tribunal/` is local state and is ignored.
- `site/` - Astro + Tailwind public site, Dockerfile, nginx config, k8s manifests, `deploy.sh`.
- `scripts/` - `deploy-contract.sh` (build, store and instantiate the contract) and `init-testnet.sh` (probe a local devnet).

## Commands

Go needs 1.23 or newer (`go.mod` says `go 1.23`). These are the steps CI runs in `.github/workflows/go.yml`:

```bash
go mod download && go mod verify
gofmt -s -d .              # must print nothing
go vet ./...
go build ./...
go test -race -count=1 ./...
go build -o tribunal ./cmd/tribunal
./tribunal --help
```

Fizzbuzz demo checks (also in CI):

```bash
(cd examples/go-fizzbuzz-verified && go test -race -count=1 ./...)
go run ./cmd/seed-fizzbuzz-demo     # must leave examples/go-fizzbuzz-verified/.tribunal/ unchanged
```

Contract (from `.github/workflows/contracts.yml`, Rust 1.85.0 with the `wasm32-unknown-unknown` target):

```bash
cd contracts/tribunal-reputation
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --release
cargo build --release --target wasm32-unknown-unknown
```

Site (scripts in `site/package.json`; `predev` and `prebuild` copy `docs/` and `.tribunal/reports/` into `site/_content/`):

```bash
cd site
npm ci
npm run dev
npm run build
```

Not verified when this file was written: the Go commands failed locally only because the machine had Go 1.22; `gofmt -s -l .` was clean. The cargo and npm commands were not run.

## Deployment

- The CLI is installed by users with `go install github.com/dpdanpittman/tribunal/cmd/tribunal@latest`. There is no release pipeline in `.github/`.
- The contract is deployed by the owner with `scripts/deploy-contract.sh`. It signs transactions with a local keyring key.
- The site runs on the owner's homelab Kubernetes cluster behind a reverse proxy. `site/deploy.sh` builds the image on a node and applies `site/k8s/`. Only the owner runs it.
- An agent does not deploy. Do not run `deploy.sh`, `deploy-contract.sh`, `kubectl`, `docker` or `xiond tx` commands. A change to a running system is a reviewed script that the owner runs.

## Rules for agents

- Ask before large changes. Explain the problem and the proposed fix first. Keep diffs small and surgical.
- Never commit secrets. API keys (`ANTHROPIC_API_KEY` and others), the contract operator key or mnemonic, and `~/.tribunal/chain.yaml` stay out of the repo. Secrets live in a password manager and are read at run time.
- Never delete this repository or rewrite published history. No force pushes to `main`.
- Do not change `.github/workflows/`, `site/Dockerfile`, `site/k8s/`, `site/deploy.sh` or `scripts/deploy-contract.sh` unless that is the task.
- Before saying a change is done, run `gofmt -s -d .`, `go vet ./...` and `go test -race -count=1 ./...`. For contract changes, run the cargo steps above. For site changes, run `npm run build`. Say plainly what you did not run.
- Commit messages: short, imperative, say what changed. Existing history uses prefixes like `docs+site:` or `vX.Y.Z:`.
- Repo traps:
  - The fizzbuzz demo seed must be deterministic. If you change ledger, finding or signing code, run `go run ./cmd/seed-fizzbuzz-demo` and check `git diff examples/go-fizzbuzz-verified/.tribunal/`. CI fails on any diff.
  - `.tribunal/` is ignored except `.tribunal/reports/`. Reports there are published on the site.
  - `site/_content/` is generated by `npm run sync`. Do not edit it by hand; edit `docs/` or `.tribunal/reports/`.
  - Since v0.5.8 every finding must carry a reproducibility field. The persona prompts in `agents/` and `skills/` enforce this, not the Go code. Do not drop it when you edit them.
  - The contract CI skips `cosmwasm-check` on purpose (it does not link on current Rust). Do not add it back without checking.
  - `scripts/deploy-contract.sh` uses the cosmwasm optimizer by default. A raw `cargo build` wasm is rejected by newer wasmd.
  - When you change a CLI command or flag, update `CHANGELOG.md` and the docs that show it.

## Do not commit or make public

This repository is public.

- No secrets: keys, tokens, mnemonics, `.env` files, `chain.yaml`, keyring files.
- No personal details about the owner.
- No internal hostnames, IP addresses, machine usernames, home directory paths or chat ids. Describe infrastructure generically ("the homelab cluster", "the reverse proxy"). Do not add more such details to `site/deploy.sh` or `site/k8s/`.
- No build output: the `tribunal` binary, `contracts/*/target/`, `contracts/*/artifacts/`, `site/dist/`, `site/node_modules/`.
